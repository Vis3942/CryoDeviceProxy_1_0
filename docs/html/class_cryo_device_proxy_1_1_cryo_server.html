◆ DeviceProtocolAsync()

async Task CryoDeviceProxy.CryoServer.DeviceProtocolAsync ( TcpClient  deviceClient)
private

This function normally runs in its own task, and handles all protocols (that is commands and responses) to a single device Firstly the tls based communications is initiated with the device. If this tls negotiation fails, the connection to the device is closed. The device periodically sends a ping packet. Two versions of the ping packet are supported in this function

Version 1.0 ping packet format is "A;B;C;D;\r" where

  • A: IMEI number
  • B: Serial number
  • C: Usage Statistics Count
  • D: Error log count

Version 1.1 ping packet format is "A;B;C;D;E;F;G;H1;...Hn\r" where

  • A: IMEI number
  • B: Serial number
  • C: Usage Statistics Count
  • D: Error log count
  • E: Firmware Version
  • F: PPU Grace treatments left
  • G: Number of language packs in device
  • Hi: Each language pack name with version number and values of i are 0...G-1

The basic functionality implemented in this function on receiving a ping packet from device is:

  1. Establish a TLS connection: if fails or exception, close connection to device
  2. Read data from stream: if error or zero bytes read, close connection to device
  3. Parse the read data into packets in the above format using Regex, remove duplicates and process each packet in a loop.
  4. Create instance of PingPacket with packet string received. If packet is not valid, write to InvalidPingData table, and close connection to device

  5. Packet Valid Actions:

    devbll.SendDevicePingData function is used to send the ping packet to the backend server. If updated successfully, the function will send a ping response appropriate for the following actions: "Ui Connection", "Error Data Download", "Usage Statistics Downlaod", or a ping response. The ping response packet contains information from the backend server and the connection status. Then this function will check to see if a connection to device is requested from user interface, if yes, establish a channel with the user interface connection object using Buffered blocks and device connection object. This setup for the device is done in the function DoUIConnection, and the corresponding setup for the User Interface happens in the function UIProtocolAsync. Once the channel exits, connection to device and user interface are closed. If a connection is not pending, the function checks to see if there are any error data available in the device. If yes, all the error logs from the device are downloaded and written to the backend server using the function DoErrorDownload. Once the error logs have been downloaded, the connection to device is closed. If there are no error data available in device, this function will check to see if there are any usage statistics in the device. If usage statistics are available, the function will download the usage statistics from device and write it to the backend server using the function DoUsageStatsDownload. Once data is downloaded, the connection to the device is closed. If there is no pending usage statistics in the device, ping response is sent to the device and the connection is closed.

◆ UIProtocolAsync()

async Task CryoDeviceProxy.CryoServer.UIProtocolAsync ( TcpClient  uiClient)
private

This function normally runs in its own task, and handles all protocols (that is commands and responses) to a single user interface Firstly the tls based communications is initiated with the user interface. If this tls negotiation fails, the connection to the user interface is closed. All connections to this socket server require an authentication token served by the backend server. Supported commands with user interface are:

  • getinfo
    [service tag]
    [email]
    [token]

The socket server queries the backend server and after authenticating the token returns [ping data];[utc time it was received]0x0d

connect
[service tag]
[email]
[token]0x0d

The socket server queries the backend server and after authenticating the token waits for device to ping data and establish a connection. This function on receiving the connect command waits for period of 15*9 seconds for a ping packet from device. If the device has not sent the ping packet, the function will end the connection to the user interface.

If the device pings within the timeout, the function initializes the connected (Y1) command to the device, and setups up BufferedBlocks that enable reading any data received from user interface and sends it to the device (through a buffer block), and conversely any data from device (through a buffer block) is sent to the user interface. If the user interface sends the "end" data or closes the connection, the above bufferblocks are closed and the connection to the user interface ends. This could also be triggered by an end command from the device (received through a BufferBlock)

Advanced Feature

In case of error in the ping data were the packet received is mal-formed the device will never get a response, and remote debuggging will not be possible. To support this special case, advacned connection options are supported. All these functions behave exactly as the connect command above but have different set of data in the command payload. The are

  • advconnectserial
    [serial number]
    [email]
    [token]0x0d
  • advconnectimei
    [imei]
    [email]
    [token]0x0d
  • advconnectid
    [id in InvalidPingPacket table]
    [email]
    [token]0x0d
